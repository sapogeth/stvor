\vspace{-1cm}\part{Fundamental Principles}
\vspace{-0.5cm}\chapter{Introduction to Stvor Messenger}
Stvor Messenger is a \textbf{post-quantum E2E-encrypted messenger} built on the \textbf{Ilyazh-Web3E2E v0.8} protocol. The project demonstrates proper design of a secure messenger with consideration for future quantum threats.
\vspace{-0.3cm}\section{Three Pillars of Architecture}
\vspace{-0.2cm}\subsection{1. Post-Quantum Cryptography (PQC)}
\textbf{Goal:} Protection against ``Harvest Now, Decrypt Later'' (HNDL) attacks
\textbf{Problem:} If an attacker records encrypted messages today, they can decrypt them in the future using a quantum computer.
\textbf{Solution:} Hybrid cryptography (classical + post-quantum simultaneously):
\begin{lstlisting}[language=]
NOT:  ECDH OR PQ_CRYPTO
YES:  ECDH AND PQ_CRYPTO (simultaneously)
shared_secret = HKDF(ecdh_secret || mlkem_secret)
\end{lstlisting}
If one mechanism is compromised, the other remains secure.
\vspace{-0.2cm}\subsection{2. Client-Side Encryption}
\begin{itemize}
  \item Private keys \textbf{NEVER} leave the browser
  \item Relay server stores only \textbf{public keys} and \textbf{encrypted messages}
  \item Decryption happens entirely on the client
  \item Relay = stateless message broker
\end{itemize}
\vspace{-0.2cm}\subsection{3. Defense-in-Depth}
Multiple independent layers of protection:
\begin{enumerate}
  \item \textbf{Transport Layer} — TLS 1.3
  \item \textbf{Relay Integrity} — Identity pinning (EREBUS mitigation)
  \item \textbf{Message Encryption} — AEAD with AAD
  \item \textbf{Traffic Analysis} — Message padding, timing jitter
  \item \textbf{User Privacy} — Toggles for typing, read receipts
  \item \textbf{PQ Downgrade} — Mandatory PQ detection
\end{enumerate}
\vspace{-0.5cm}\chapter{Cryptographic Protocol}
\vspace{-0.3cm}\section{Ilyazh-Web3E2E Architecture Overview}
\vspace{-0.2cm}\subsection{Layer 1: Handshake (Authenticated Key Exchange)}
Hybrid key exchange with dual signatures:
\begin{lstlisting}[language=]
Client A                          Client B
1. Fetch B's prekeys from relay
   → identity: Ed25519 + ML-DSA pub keys
   → signed prekey: X25519 + ML-KEM pub keys
2. A generates ephemeral keys
   → X25519 ephemeral keypair
   → ML-KEM-768 ephemeral keypair
3. A creates handshake
   → ECDH(A.eph_x25519, B.id_x25519)
   → KEM_encap(B.mlkem_pubkey) → shared_secret, ct
   → Sign with Ed25519 + ML-DSA-65
4. A sends handshake to relay (POST /api/message/:chatId)
   → messageType: 'handshake'
   → Relay stores as blob with blobRef = SHA256(data)
5. B receives handshake (via WebSocket or polling)
   → ECDH(B.id_x25519_secret, A.eph_x25519_pub)
   → KEM_decap(B.mlkem_secret, A.mlkem_ct)
   → Verify Ed25519 signature
   → Verify ML-DSA signature
   → Compute session ID = SHA256(transcript)
6. B sends response handshake
   → Same structure, no ephemeralMLKEM/ciphertext fields
7. A receives response
   → Verifies all B's signatures
   → Sets pqMandatory = true (both support PQ)
   → Session ready
✅ E2E encrypted session established
\end{lstlisting}
\vspace{-0.2cm}\subsection{Layer 2: Double Ratchet}
\subsubsection{Ratchet State}
\begin{lstlisting}[language=TypeScript]
interface RatchetState {
  sessionId: Uint8Array              // 32 bytes, unique per session
  rootKey: Uint8Array                // 64 bytes, from ECDH + KEM
  sendChainKey: Uint8Array           // 64 bytes, evolves per message
  recvChainKey: Uint8Array           // 64 bytes, evolves per message
  sendRatchetId: bigint              // 8 bytes, epoch counter
  recvRatchetId: bigint              // 8 bytes, epoch counter
  sendCounter: number                // 4 bytes, per-epoch counter
  recvCounter: number                // 4 bytes, per-epoch counter
  epochStartTime: number             // Timestamp when epoch began
  sessionStartTime: number            // Timestamp when session started
  totalMessages: number              // Total messages in session
  pqMandatory: boolean               // Downgrade protection
}
\end{lstlisting}
\subsubsection{Mandated Re-encapsulation Cadence}
Mandatory DH ratchet every:
\begin{itemize}
  \item \textbf{2\textsuperscript{20}} (1M) messages in epoch, OR
  \item \textbf{24 hours} from epoch start, OR
  \item \textbf{2\textsuperscript{32}} (4B) total session messages, OR
  \item \textbf{7 days} from session start
\end{itemize}
\vspace{-0.2cm}\subsection{Layer 3: Per-Message Encryption (AEAD)}
\subsubsection{For each message:}
\begin{enumerate}
  \item \textbf{Rekeying check}
  \begin{lstlisting}[language=TypeScript]
needsRekey(state) → {
  required: boolean,
  reason?: 'message_limit' | 'time_limit' | 'session_cap_messages' | 'session_cap_time'
}
  \end{lstlisting}
  \item \textbf{Message key derivation}
  \begin{lstlisting}[language=]
mk = HKDF-SHA256(sendChainKey, label="mk", 32)
  \end{lstlisting}
  \item \textbf{AAD (Additional Authenticated Data) construction}
  \begin{lstlisting}[language=]
AAD = Version(1) || SuiteID(8) || SessionID(32) ||
      Sequence(8) || Epoch(8) || Flags(1)
= 58 bytes total
  \end{lstlisting}
  \item \textbf{Nonce construction}
  \begin{lstlisting}[language=]
nonce = ratchetId || counter
= 8 bytes || 4 bytes = 12 bytes total (GCM requires 12)
  \end{lstlisting}
  \item \textbf{Message padding (defense-in-depth)}
  \begin{lstlisting}[language=TypeScript]
padded = padMessage(plaintext, {
  blockSize: 256 | 512 | 1024,  // Align to power-of-2
  strategy: 'random' | 'pkcs7'
})
  \end{lstlisting}
  \item \textbf{AEAD encryption}
  \begin{lstlisting}[language=]
ciphertext = AES-256-GCM(mk, nonce, padded_plaintext, aad)
Output: ciphertext + 16-byte auth tag
  \end{lstlisting}
  \item \textbf{Send to relay}
  \begin{lstlisting}[language=TypeScript]
blobRef = SHA256(ciphertext_blob)
POST /api/message/:chatId → {
  blobRef,
  encryptedBlob,
  timestamp
}
Relay response: { sequence, timestamp }
  \end{lstlisting}
\end{enumerate}

\vspace{-1cm}\part{Security}
\vspace{-0.5cm}\chapter{Defense-in-Depth}
\vspace{-0.3cm}\section{Four Independent Security Layers}
\vspace{-0.2cm}\subsection{Layer 1: Relay Network Integrity (EREBUS)}
\textbf{Problem:} MITM can substitute relay server
\textbf{Solution:} Application-layer identity pinning
\begin{verbatim}
Protocol:
1. Client generates nonce (32 bytes, random)
2. Client → Relay: { action: "relay_challenge", nonce }
3. Relay → Client: { action: "relay_response", signature, pubkey }
4. Client verifies:
   - SHA256(pubkey) == expectedIdentityKeyHash ✓
   - Ed25519.verify(signature, nonce, pubkey) ✓
Result: Client is certain relay is authentic (not impostor)
\end{verbatim}
\vspace{-0.2cm}\subsection{Layer 2: Traffic Analysis Resistance}
\textbf{Problem:} Message size and timing reveal content
\textbf{Solution:} Message padding + timing smoothing
\begin{lstlisting}[language=TypeScript]
padMessage(plaintext: Uint8Array, config: PaddingConfig) {
  // Add random padding
  // Align to power-of-2: 256, 512, 1024 bytes
  // All messages same size → traffic analysis resistant
}
Result: Attacker cannot infer content from message size
\end{lstlisting}
\vspace{-0.2cm}\subsection{Layer 3: User Privacy Controls}
\textbf{Problem:} Typing indicators, read receipts reveal activity
\textbf{Solution:} User toggles for privacy

interface PrivacySettings {
  disableTypingIndicators: boolean
  disableReadReceipts: boolean
  fakingEnabled: boolean            // Send decoy messages
  decoyMessageFrequency: number      // How often (ms)
  anonymizeMessageTiming: boolean    // Add jitter
}
\end{lstlisting}
\vspace{-0.2cm}\subsection{Layer 4: PQ Downgrade Detection}
\textbf{Problem:} Attacker forces classical-only, decrypts with QC later
\textbf{Solution:} Mandatory PQ if both sides support
\begin{lstlisting}[language=]
Handshake Protocol:
- A claims: pqSupported = true
- B claims: pqSupported = true
→ Session state: pqMandatory = true
Effect:
- If pqMandatory=true, MUST use PQ
- If PQ unavailable (stubs) → handshake FAILS
- No silent downgrade to classical
\end{lstlisting}

\vspace{-0.2cm}\subsection{Stage 1: Session Initialization (Handshake)}
\begin{verbatim}
CLIENT A                          CLIENT B              RELAY
[1] A.getPrekeys(B)
    ────────────────────────────────────→
                                          [2] Relay returns:
                                              - B.identity_keys
                                              - B.signed_prekey
                                              - B.one_time_prekey
    ←────────────────────────────────────
[3] A.generateEphemeralKeys()
    - X25519 ephemeral
    - ML-KEM-768 ephemeral

    - Sign with Ed25519 + ML-DSA
[4] A.sendHandshake()
    ────────────────────────────────────→
                                          [5] Relay stores
                                              messageType='handshake'
[6] B.getMessages()
    ←────────────────────────────────────
[7] B.processHandshake()
    - ECDH + KEM_decap
    - Verify Ed25519 + ML-DSA
    - Compute sessionId
    - pqMandatory=true
[8] B.sendResponse()
    ────────────────────────────────────→
[9] A.finalizeSession()
    - Verify B's signatures
    - Identical session keys
✅ Session ready for encryption
\end{verbatim}
\vspace{-0.2cm}\subsection{Stage 2: Send Encrypted Message}
\begin{verbatim}
CLIENT A                          RELAY              CLIENT B
[1] User types "Hello"
[2] A.checkRekeying()
    - 2^20 messages? 24h? 2^32 total? 7 days?
    - If needed: perform DH ratchet step
[3] A.encryptMessage()
    - mk = HKDF(chainKey, "mk", 32)
    - AAD = Version || Suite || SessionID || Seq || Epoch || Flags
    - plaintext = { content, timestamp, sender }
    - padded = padMessage(plaintext)
    - ciphertext = AES-256-GCM(mk, nonce, padded, aad)
[4] A.storeOnRelay()
    ────────────────→
    POST /api/message/:chatId
    { blobRef, ciphertext }
[5] Relay stores blob
    blobRef = SHA256(ciphertext)
    { chatId, blobRef, sender, sequence, timestamp }
[6] Relay broadcasts via WebSocket
    ────────────────────────────────────→
[7] B.receiveMessage()
    - Extract ratchetId, counter
    - Check: AAD sessionId matches local
    - If mismatch → AADMismatchError (get session from relay)
[8] B.decryptMessage()
    - mk = HKDF(chainKey, "mk")
    - plaintext = AES-256-GCM.decrypt(mk, nonce, ciphertext, aad)
    - Unpad message
[9] B.displayMessage()
    "Hello" shown in UI
[10] B.sendReadReceipt() [if enabled]
     ────────────────→
     WebSocket: { type: 'read', sequence }
✅ Message delivered and decrypted E2E
\end{verbatim}
\vspace{-0.2cm}\subsection{Out-of-Order Message Handling}
If B receives message \#10 before message \#5:
\begin{verbatim}
Problem: Can't decrypt #10 (chainKey not advanced to counter 10)
Solution: Skipped Keys Storage
1. When advancing chainKey:
   For each skipped counter (5-9):
     mk[i] = HKDF(ck, "mk")
     Save: { ratchetId, counter, mk[i] } in skipped_keys
   Limit: max 100 skipped keys
2. When delayed message arrives:
   Check skipped_keys[counter]
   If found: decrypt with mk[counter]
   If not found: drop message (impossible to decrypt)
3. Cleanup:
   Delete keys older than 24 hours
   Delete if exceeds limit (FIFO)
Result: Out-of-order tolerance up to 100 messages
\end{verbatim}

\vspace{-0.3cm}\section{Key Concepts}
\vspace{-0.2cm}\subsection{Forward Secrecy}
If a ratchet key on day 5 is compromised, it does not compromise messages from days 1-4 and 6-7. Each ratchet step generates a new chain key.
\vspace{-0.2cm}\subsection{Post-Quantum Hybrid}
\begin{verbatim}
NOT:  ECDH OR ML-KEM
YES:  ECDH AND ML-KEM (simultaneously)
shared_secret = HKDF(ecdh_secret || mlkem_secret)
If ECDH compromised → ML-KEM still provides PQ security
If ML-KEM broken → ECDH still provides classical security
\end{verbatim}
\vspace{-0.2cm}\subsection{Perfect Forward Secrecy}
Key compromise doesn't help decrypt past messages. Ratcheting with DH updates every N messages.
\vspace{-0.2cm}\subsection{Authenticated Key Exchange}
Both parties are certain of each other's identity. Therefore signatures (Ed25519, ML-DSA) over transcript are used.
\vspace{-0.2cm}\subsection{Out-of-Order Tolerance}
Messages may arrive out of order. Skipped keys store mk for skipped counters.

\vspace{-0.5cm}\chapter{Mathematical Foundations}
\vspace{-0.3cm}\section{Required Mathematical Knowledge}
\vspace{-0.2cm}\subsection{Number Theory}
\begin{itemize}
  \item \textbf{Modular Arithmetic:} $(a + b) \bmod n$, $(a \cdot b) \bmod n$, $(a^b) \bmod n$
  \item \textbf{Prime Numbers:} Definition, primality testing, generation
  \item \textbf{Coprime Numbers:} $\gcd(a, b) = 1$, Euler's totient function $\phi(n)$
  \item \textbf{Multiplicative Order:} $\text{ord}_n(a)$ — smallest $k$ such that $a^k \equiv 1 \pmod{n}$
  \item \textbf{Primitive Root:} Generator of group $(\mathbb{Z}_p^*, \cdot)$
\end{itemize}
\vspace{-0.2cm}\subsection{Algebra and Group Theory}
\begin{itemize}
  \item \textbf{Groups:} Set $G$ with operation $\cdot$ and properties: closure, associativity, identity element, inverse elements
  \item \textbf{Cyclic Groups:} Group generated by single element $g$: $G = \langle g \rangle = \{g^0, g^1, g^2, \ldots\}$
  \item \textbf{Subgroups:} Subset of group closed under the operation
  \item \textbf{Element Order:} $|a| = \min\{k : a^k = e\}$
  \item \textbf{Lagrange's Theorem:} If $H$ is subgroup of $G$, then $|H|$ divides $|G|$
\end{itemize}
\vspace{-0.2cm}\subsection{Elliptic Curves}
\begin{itemize}
  \item \textbf{Curve Equation:} $y^2 = x^3 + ax + b$ (Weierstrass form)
  \item \textbf{Points on Curve:} Set of $(x, y)$ satisfying equation, plus point at infinity $\mathcal{O}$
  \item \textbf{Point Addition:} If $P$, $Q$ are points, then $P + Q$ is third intersection of line $PQ$ with curve
  \item \textbf{Point Doubling:} $P + P = 2P$ — intersection of tangent at $P$ with curve
  \item \textbf{Scalar Multiplication:} $[k]P = P + P + \cdots + P$ ($k$ times), computed efficiently via binary method
  \item \textbf{Order:} Smallest $n > 0$ such that $[n]P = \mathcal{O}$
\end{itemize}
\vspace{-0.2cm}\subsection{Discrete Logarithm (DLP)}
\begin{itemize}
  \item \textbf{Problem:} Given: $g, h = g^x \in G$. Find: $x$ (discrete logarithm)
  \item \textbf{Complexity:} Subexponential on $\mathbb{F}_p^*$, exponential on elliptic curve groups
  \item \textbf{ECDLP (Elliptic Curve DLP):} Given $P, Q = [x]P$ on curve $E$. Find $x$. Considered hard problem for correctly chosen curve
  \item \textbf{Application in X25519:} Key exchange via Diffie-Hellman on Curve25519
\end{itemize}
\vspace{-0.2cm}\subsection{Diffie-Hellman and ECDH}
\begin{itemize}
  \item \textbf{DH in $\mathbb{F}_p^*$:} Alice: $a_{\text{secret}}, a_{\text{pub}} = g^a \bmod p$. Bob: $b_{\text{secret}}, b_{\text{pub}} = g^b \bmod p$. Shared: $s = b_{\text{pub}}^a = g^{ab} \bmod p$
  \item \textbf{ECDH on Curve:} Alice: $a$, $A = [a]P$. Bob: $b$, $B = [b]P$. Shared: $S = [a]B = [b]A = [ab]P$
  \item \textbf{X25519:} Specially optimized ECDH implementation on Curve25519, 32-byte (256-bit) input size
  \item \textbf{Security:} Based on hardness of ECDLP
\end{itemize}
\vspace{-0.2cm}\subsection{Hashing and Hash Functions}
\begin{itemize}
  \item \textbf{Properties:} Determinism, speed, avalanche effect (tiny change → complete output change)
  \item \textbf{Preimage Resistance:} Impossible to find $x$ given $h(x)$
  \item \textbf{Second Preimage Resistance:} Impossible to find $x' \neq x$ such that $h(x) = h(x')$
  \item \textbf{Collision Resistance:} Impossible to find $x, x'$ such that $h(x) = h(x')$
  \item \textbf{SHA-256:} Standard hash function, 256-bit output, used in HKDF and content-addressed storage
\end{itemize}
\vspace{-0.2cm}\subsection{Key Derivation Functions (KDF and HKDF)}
\begin{itemize}
  \item \textbf{KDF:} Function that takes non-standard input (may be low-entropy) and produces cryptographically strong key
  \item \textbf{HKDF (HMAC-based KDF):} Two-stage process: Extract then Expand
  \item \textbf{Extract:} $\text{PRK} = \text{HMAC}(\text{salt}, \text{IKM})$ — concentrates entropy
  \item \textbf{Expand:} $\text{OKM} = \text{PRK} + \text{HMAC}(\text{PRK}, \text{info} || 0x01) + \ldots$ — expands to required key material
  \item \textbf{In Stvor:} $\text{shared\_secret} = \text{HKDF}(\text{ecdh\_secret} || \text{mlkem\_secret})$ — combines two entropy sources
\end{itemize}
\vspace{-0.2cm}\subsection{Authenticated Encryption (AEAD)}
\begin{itemize}
  \item \textbf{Properties:} Confidentiality (CPA security) + Integrity (authenticity)
  \item \textbf{AES-GCM:} Advanced Encryption Standard in Galois/Counter Mode
  \item \textbf{Components:} Key $K$, Nonce $N$ (12 bytes for GCM), Plaintext, AAD (Additional Authenticated Data)
  \item \textbf{Output:} Ciphertext + Authentication Tag (16 bytes)
  \item \textbf{AAD:} Authenticated but not encrypted; in Stvor contains session metadata (SessionID, Sequence, Epoch)
\end{itemize}
\vspace{-0.2cm}\subsection{Digital Signatures}
\begin{itemize}
  \item \textbf{Algorithm:} $(pk, sk) \leftarrow \text{KeyGen}()$, $\sigma \leftarrow \text{Sign}(sk, m)$, $\text{Verify}(pk, m, \sigma) \in \{\text{True}, \text{False}\}$
  \item \textbf{Properties:} Authentication (only $sk$ holder can create signatures), Non-repudiation (cannot deny signature)
  \item \textbf{EdDSA (Ed25519):} Edwards curve signatures, 64-byte signature, deterministic (no randomness needed)
  \item \textbf{ML-DSA-65 (CRYSTALS-Dilithium):} Post-quantum signature based on module lattices, ~3309 bytes
  \item \textbf{Dual Signature in Stvor:} Message signed with both — Ed25519 and ML-DSA-65
\end{itemize}
\vspace{-0.2cm}\subsection{Key Encapsulation (KEM)}
\begin{itemize}
  \item \textbf{Algorithm:} $(pk, sk) \leftarrow \text{KeyGen}()$, $(K, c) \leftarrow \text{Encap}(pk)$, $K \leftarrow \text{Decap}(sk, c)$
  \item \textbf{Output:} Shared secret $K$ (symmetric key) and encapsulated ciphertext $c$
  \item \textbf{ML-KEM-768 (CRYSTALS-Kyber):} Post-quantum KEM based on module lattices
  \item \textbf{Sizes:} Public key: 1184 bytes, Ciphertext: 1088 bytes, Shared secret: 32 bytes
  \item \textbf{Security:} IND-CPA (passive eavesdropping) → IND-CCA2 (chosen ciphertext) with modifications
\end{itemize}
\vspace{-0.2cm}\subsection{Lattices and Post-Quantum Cryptography}
\begin{itemize}
  \item \textbf{Lattice:} Discrete subgroup of $\mathbb{R}^n$ generated by linearly independent vectors
  \item \textbf{Shortest Vector Problem (SVP):} Find non-zero vector with minimum length in lattice — considered hard even for quantum computers
  \item \textbf{Closest Vector Problem (CVP):} Find lattice vector closest to arbitrary point
  \item \textbf{LWE (Learning With Errors):} Given $n$ random pairs $(a_i, b_i)$ where $b_i = \langle a_i, s \rangle + e_i \bmod q$. Find $s$.
  \item \textbf{MLWE (Module-LWE):} Variant of LWE over polynomial rings, foundation of ML-KEM and ML-DSA
\end{itemize}
\vspace{-0.2cm}\subsection{Probability and Statistics}
\begin{itemize}
  \item \textbf{Probabilistic Statements:} Birthday paradox ($n \approx 2^{128}$ for 50\% collision chance in 256-bit function)
  \item \textbf{Statistical Distance:} Maximum difference between two probability distributions
  \item \textbf{Negligible Function:} $\text{negl}(\lambda) = O(1/\lambda^c)$ for any $c$; in cryptography: security parameter $\lambda = 128$
  \item \textbf{Probabilistic Polynomial Time Algorithm:} PPT — can be run multiple times, yields correct results with high probability
\end{itemize}
